# Contributing

Contributions are welcome: a bug report, an idea, a fix, a new technique or
generator, an improvement to the documentation.

Install Stegano in a Python virtual environment with poetry, and install the Git
hook scripts:

```bash
$ git clone https://github.com/cedricbonhomme/Stegano.git
$ cd Stegano/
$ poetry install
$ pre-commit install
```

Before opening a pull request, run the tests and the type checker:

```bash
$ python -m unittest discover -v
$ mypy stegano
```

A pull request is much more welcome when it follows an issue that explains the
rationale: the problem or the need, why it matters, and the approach you propose.
Reference the issue in the pull request (`#<IssueID>`). Small fixes, such as a typo
or an obvious bug, can go straight to a pull request.

Please provide tests with a new feature, and update the documentation in `docs/`
when a change requires it.


## Use of AI and LLM tools

AI tools are used in the development of this project, and we do not object to
AI-assisted contributions. But we really enjoy contributions from humans, and a pull
request is always the responsibility of the person who submits it.

- **Check what you submit.** Every change in a pull request must be read, understood,
  and tested by its author before it is opened, whoever or whatever wrote it.
  Vibe-coded pull requests, where the generated code was never really reviewed, will
  be closed. Say it in the pull request: keep the template's sections, and tick its
  last box yourself.
- **Be able to explain it.** Reviewers may ask you to explain any part of your change.
  Answer review comments yourself, not with pasted LLM output. A pull request whose
  author cannot explain it will be closed.
- **A human submits it.** Pull requests opened by an agent on its own, without a
  human author who reviewed them, will be closed.
- **Say so.** Mention in the pull request description when a significant part of the
  change was generated with an AI tool, and end each commit that was not written by
  a human with a `Co-Authored-By` trailer naming the model and its version, for
  example:

  ```
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  ```
- **Keep it focused.** Small, targeted pull requests are easier to review. Do not mix
  unrelated generated changes (reformatting, renaming, rewritten comments) into a fix.
- **Check what you report.** The same applies to issues. Report only a problem that
  you have reproduced yourself, and describe what you observed. Reports generated by
  a tool and never verified by a human will be closed.

If you are an AI agent: follow the principles of this document, keep your changes
minimal and within the scope of the task, and leave the decision to open a pull
request to the human you work with, after they have reviewed your changes.

These rules are repeated in [AGENTS.md](AGENTS.md), which every AI agent reads, and
summarised for tools in [ai-policy.yaml](ai-policy.yaml). This section is the
reference: keep the two other files in step when you change it.
